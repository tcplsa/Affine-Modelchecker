# Directional PDR Design

For an AIGER transition system with latch state `s`, input `u`, initial set
`I(s)`, transition relation `T(s,u,s')`, constraints `C(s,u)`, and bad
predicate `B(s,u)`, the original reachability question is:

```text
I(s0) and T(s0,u0,s1) and ... and B(sk,uk)
```

## Forward PDR

Forward mode keeps the original relation. Its source frame is `F0 = I`, and
proof obligations are generated by asking whether a frame state can reach
`B` in one transition.

## Reverse PDR

Reverse mode defines:

```text
T_reverse(r,v,r') := T(r',v,r)
source(r)          := exists u. C(r,u) and B(r,u)
target(r)          := I(r)
```

Thus a reverse trace from `B` to `I` is exactly an original trace from `I` to
`B` in the opposite order. The implementation uses separate unprimed inputs
for bad-state membership and primed inputs for the predecessor transition.
This matters when the input that makes `B` true differs from the input used on
the preceding transition.

Reverse transitions are relational and may have many successors. The engine
keeps a complete SAT latch assignment as the concrete witness while separately
trying a conservative UNSAT-core lift for the blocking obligation. If the lift
query is SAT, the obligation remains the complete state. Every reverse
counterexample is simulated before it is reported; if a lifted chain is
spurious, the lane disables reverse lifting and restarts exact reverse PDR while
retaining already certified permanent lemmas.

## Bidirectional Mode

Parallel PDR lanes are configured explicitly with `--forward-aig`,
`--forward-xag`, `--reverse-aig`, and `--reverse-xag`. At selected synchronized
step boundaries the coordinator pauses the selected forward/reverse pair and
asks for a concrete bridge edge:

```text
F_i(s) and T(s,u,s') and R_j(s')
```

`F_i` and `R_j` are over-approximations, so a SAT bridge is only a candidate.
The complete latch assignments from the SAT model are checked independently:

1. Forward PDR tries to block `s` from `F_i`.
2. If that fails and yields `Init -> ... -> s`, reverse PDR tries to block `s'`
   from `R_j`.
3. If that also fails and yields `s' -> ... -> Bad`, the two traces are joined
   with the already validated edge `s -> s'`.

Before reporting UNSAFE, the joined witness is simulated through the original
gate and latch equations, including constraints and the final bad predicate. If
validation fails, middle meeting is disabled for that run and the two PDR
engines continue normally.

If either blocking attempt succeeds, its generalized lemma remains in that
direction and removes a spurious overlap. Either PDR may also independently
converge or find a counterexample.

The AIG and XAG lanes in the same direction exchange learned lemmas. A lemma is
serialized as signed latch ordinals rather than local DIMACS literals, then
mapped back through the receiver's input/latch layout. The channel direction is
part of its identity: a forward lemma is never imported by a reverse lane, and
vice versa. Imported lemmas retain the sender's proved frame level, are installed
in all lower solver frames, and are not broadcast again. Lemmas above the
receiver's current depth wait in a pending queue until that frame exists.

This is not exact BDD-style BFS: the frontiers remain PDR over-approximations.
The bridge SAT query and two anchored blocking failures provide the exactness
needed before declaring a path.

When either worker independently proves SAFE or finds a counterexample, it
publishes the result atomically. The other worker is cancelled, including an
active CaDiCaL query through the IPASIR termination callback. A cancelled SAT
query returns `UNKNOWN`; this is propagated as cancellation rather than being
treated as SAT or UNSAT.

The default policy checks one bridge every eight completed rounds. It can be
adjusted for experiments:

```sh
MC_BIDIR_MEET_INTERVAL=1 MC_BIDIR_BRIDGE_BUDGET=4 \
  ./modelchecker --forward-aig 1 --forward-xag 1 \
    --reverse-aig 1 --reverse-xag 1 example.aig
```

Each lane option takes a count from `0` to `128`. In addition to AIG/XAG,
`--forward-aig-compact`, `--forward-xag-lowered`,
`--reverse-aig-compact`, and `--reverse-xag-lowered` expose the representation
ablation controls. Counts can be asymmetric, and
inductive lemma sharing can be enabled whenever one direction has more than one lane. If none of
the lane options is supplied, or all supplied counts are zero, the program runs
one ordinary forward PDR using the representation selected by `-aig`,
`-aig-compact`, `-xag-lowered`, or `-xag`.
Lane creation is incremental: when an already started lane publishes SAFE or
UNSAFE, remaining lane configurations are not started.

- `MC_BIDIR_MEET_INTERVAL` controls the number of PDR rounds between meetings.
- `MC_BIDIR_BRIDGE_BUDGET` controls how many candidates are processed per
  meeting round. Set it to `0` to retain parallel dual-PDR search without middle
  checks.
- Multi-lane runs exchange only permanent inductive clauses by default. Set
  `MC_PDR_SHARE=0` to disable sharing. A sender publishes a clause `C` only after
  proving source disjointness and `P & C & T -> C'` without any frame-local or
  previously shared lemma. Receivers can therefore install it in every frame
  without another SAT validation.
- `MC_PDR_SHARE_INDUCTIVE_BUDGET` bounds self-induction checks per propagation
  round and lane. Default: `8`; set it to `0` to consume shared clauses without
  trying to publish new ones.
- `MC_PDR_SHARE_QUEUE` bounds each directional exchange channel. Default:
  `100000` lemmas.
- `MC_PDR_SHARE_MAX_CUBE` limits exported cube length. Default: `64`; use `0`
  for no length limit.
- `MC_PDR_SHARE_BATCH` limits messages consumed at one polling point. Default:
  `256`.
- A single PDR uses fixed seed `1` by default. Parallel lanes use a fresh random
  process seed and derive a distinct seed for each lane. Setting `MC_PDR_SEED`
  explicitly switches every lane back to deterministic seeds derived from that
  value, which is useful for reproducing an experiment.
- `MC_PDR_REVERSE_LIFT=0` disables conservative reverse obligation lifting. It
  is useful as an exact-state baseline when measuring the optimization.

## Limitations

- Reverse certificate emission is disabled; a reverse invariant is not the
  forward AIGER certificate currently produced by this code.
- Lemmas can only be shared between lanes with the same search direction.
  Sharing one across directions would be unsound because the source frames are
  different (`Init` versus `Bad`).
- Reverse lifting is conservative and often falls back to complete states
  because the transposed transition relation is nondeterministic. It therefore
  cannot generally match the lifting strength of forward PDR.
- Bridge processing takes the selected forward and reverse engine locks. A
  costly bridge blocking attempt can pause that pair until it completes.
