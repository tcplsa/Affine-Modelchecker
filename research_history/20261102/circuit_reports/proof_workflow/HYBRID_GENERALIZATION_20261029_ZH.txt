混合证明流程的从零测试：包括 LLM 时间的跨性质实验
运行目录 hybrid-generalization-20261029；本轮于北京时间2026-10-30完成

本轮问题

  上轮 p18 只证明了“有了合适候选以后，拆分和独立 IC3 有用”。这轮从原始
  模型开始，计入 LLM 调用、失败候选、证明及归档成本，检查能否在更多性质
  上受益，并尝试普通 IC3 1800 秒超时的题目。原 I/T/A/bad 不修改。

预先固定的六题

  p18：多操作指令异常后的总线检查。开发控制题，曾用于设计桥接流程。
  p568：操作数 B 从写回级前递的检查。本轮前未参与 LLM 候选调试。
  p131：WFI 睡眠状态检查。本轮前只有短基线，未参与 LLM 候选调试。
  p151：睡眠时 debug 请求检查。本轮前只有短基线，未参与 LLM 候选调试。
  p530：POP 序列长度上界。已有 stock IC3 1800 秒超时记录，LLM 曾失败。
  p256：调试触发器 hit 标志设置。相同 BTOR 的普通 IC3 已在1800秒超时。

  以上仍是同一个 CPU 家族中的不同性质，不是六种独立硬件设计。
  没有把开发题混称为未知测试题。p019/p340 缺少精确同名的官方 BTOR，未
  偷换为相近编号；p88 的22MB模型超过完整上下文640KiB上限，本轮不纳入。
  cohort.json 和 protocol-lock.json 在新结果出现前固定了选择、预算及代码。
  六题的 source_records 都为空：本轮给 LLM 的是完整字级 BTOR 及结构统计，
  没有与节点逐项对应的原 RTL 源码。这是在检验当前实际接口，不能据此断言
  “带原 RTL 语义的 LLM 分析也没有效果”。

固定流程

  原题 → 短 BMC/SMT → LLM 生成关系 → 编译及原模型保持检查 → 拆分 SMT。
  若第一条根步骤通过，最多剩4条未闭合义务，则把这些子句合为 H，保留完整
  原 I/T/A，独立交给普通 IC3。H 若 SAFE，与其余归纳义务一起推出原目标。
  H 若 UNSAFE，只能说明候选有错；原电路 UNSAFE 仍需要原性质的可达见证。
  独立证明或拆分失败时，将实际反馈交给下一轮，最多两轮；不手工补候选。

  这次 prompt 明确说明“候选可以由 IC3 证明，不必单独满足一步归纳”，避免
  模型仅为得到容易证明的关系而删除有用的非单步归纳候选。提示固定适用于
  全部题目，不含 p18 旧候选或人工写入的节点关系。

预算与计时

  每题：普通 IC3 和 hybrid 各1800秒总预算、一个本地CPU、16GiB、相同
  二进制和模型。普通 IC3 seed=730001。混合方法每轮 SMT 上限300秒、
  独立 IC3 上限600秒、单次 API 上限900秒、131072个推理/输出 token。
  所有阶段还受到剩余总预算约束。六题最多12次 API 调用，成功即停止。
  基线6题并行，混合方法2题并行，各题绑定不同CPU；整机负载没有隔离。
  远端 API 另用计算资源，本地“单核”不代表双方总计算资源完全相同。

  total_seconds：从该题启动到最终验收结束，包含所有失败尝试和查询压缩。
  llm_api_wall_seconds：全部实际 API 请求的等待时间，包括失败调用。
  proof_stage_wall_seconds：BMC、SMT、残余 IC3、组合及查询归档阶段。
  other_wall_seconds：解析、候选检查、上下文整理等余下时间。
  三者之和严格等于 total_seconds。共享 prepare 成本另列并计入成对比值。
  固定候选 development-replay 是开发检查，不放进正式从零性能结果。

  关系；p151 第二轮已使根步骤通过，但其独立核心关系600秒未闭合。

  为排除接口兼容性影响，另把 p568/p256 保存的第二轮响应按结合律把三元
  or 展开为二元 or。节点、常数、关系和其他结构均不改，不新增 API 调用。
  修正后的回放分别用了15.1秒和11.8秒，仍为 UNKNOWN：两题的原目标归纳
  步骤均为 SAT，因此不能进入“根步骤已闭合后证明辅助关系”的桥接分支。
  这些是事后兼容性检查，不覆盖主记录，也不当作新的端到端计时。

  候选质量不能只数“通过了多少辅助关系”。主实验有9轮真正进入拆分证明，
  其中8轮的根步骤仍未闭合。比如 p131 两轮都是13个子句通过12个，剩下的
  恰好是原目标；这种高通过率没有转化成解题收益。仅 p151 第二轮闭合根
  步骤，随后卡在辅助关系的独立证明。明细见 candidate-usefulness.json。

独立的结构模板对照：不计作 LLM 成功

  在看到第一批冷启动候选失败后，增加了一项明确标为事后探索的对照。
  程序从模型中识别同一种采样监视器结构，而不是手填题号或节点号：
    s' = C；前一拍时钟 q' = clk；e = ({q,clk} == 01)；
    监视器在 e 时选择 s，否则保持 h，并由外层复位条件屏蔽。
  生成三个尚未证明的候选：C→e、s→q、h=0。
  前一个独立交给 IC3，后两条及原目标的归纳步骤由 SMT 检查并组合。
  模式不匹配、关系不成立或任何必要证明未闭合，都不能报告原题 SAFE。

  该对照不用 API，候选提取和子进程启动时间也计入完整管线：
    p18：SAFE 32.8秒；基线874.9秒。
    p568：SAFE 197.3秒；基线82.2秒，反而更慢。
    p530/p256/p131/p151：短尝试均 UNKNOWN，独立核心关系500秒超时。
  固定提取程序为运行目录中的 phase_templates.py。三条关系和时钟节点来自
  图结构匹配，不读取旧的 LLM 候选。p18 用于设计规则，不能当独立验证集。

  另有 p18 控制试验把 C→e 弱化为 C→clk，也能闭合，但用了269.3秒。
  更弱的关系在这一次反而更慢，说明候选正确与否、强弱、后端证明代价必须
  分别评估。它不能证明强关系一般都更好。

为什么拆分之后仍然可能很难

  实测闭合依赖锥的状态位数，原题→核心关系如下：
    p18 6635→6631；p530 6443→6439；p568 6443→6439；
    p256 6445→6441；p131 6706→6702；p151 6503→6499。
  每题都只减少4个监视器状态位。原 I/T/A 始终完整保留；这里不是把复杂 CPU
  缩成一个很小的模块。state 还包含无 next 的自由输入编码，不能直接当作
  实际硬件触发器数。统计依据为 residual-cone-audit.json。

  当前方案主要改变证明目标的表达和分工。p18 的目标调整确实有效，但
  其余难题的内部条件仍依赖同样大的状态网络，未被自动消除。因而“小的
  子目标公式”不意味着“小的可达性问题”，也不意味着继续增加 token 会解决。

本地额外尝试（与主实验分开）

  原生 wl-kind 入口因当前构建没有 Bitwuzla 而报错。这是后端不可用，不能
  算成字级算法在这些题上失败。随后用已有 Z3 对同一核心关系做多步归纳：
    p530：k=2 为 SAT，k=4/8/16 各20秒超时。
    p256：k=2/4 为 SAT，k=8/16 各20秒超时。
    p131：k=2 为 SAT，k=4/8/16 各20秒超时。
  SAT 指归纳步骤反例，不是从原初始化可达的硬件漏洞；没有因此报告 SAFE。
  再把 p530/p131 的 k=4 单项预算提高到300秒，分别在46.7秒和275.3秒得到
  SAT。说明此前20秒超时遮住了“该关系尚非4步归纳”的结果；单纯延长这一步
  并不会得到完整证明。包括查询生成及归档的两次总时间为47.8秒、276.5秒。

  对普通 IC3 已确认1800秒超时、且短模板证明的核心关系超时的全部四题，
  各做一次新1800秒上限的长尝试，核心 IC3 上限1700秒。长短尝试分别保存，
  探索总成本不隐去。四次长尝试均已结束：
    p530 UNKNOWN 1710.8秒；p256 UNKNOWN 1711.4秒；
    p131 UNKNOWN 1712.9秒；p151 UNKNOWN 1710.8秒。
  四题都是独立核心关系到达1700秒上限，主目标仍无证明；不是发现了漏洞。
  因而本轮1800秒基线超时题的突破数是0/4，不能写成“解决了两个难题”。

这一轮能下什么结论

  1. 框架已能完成自动候选、义务拆分、独立可达性证明、组合验收和完整计时。
     17项回归测试通过，所有正式运行的模型、工具、源码快照和计时核对通过。
     835份已归档查询的解压内容也逐一通过哈希检查。验收不等于算法有效。

  2. 当前从零 LLM 流程没有证明出六题中的任何一题；不能据此宣传跨样例加速。
     结构模板在开发题 p18 上有明确收益，在另一个可解题 p568 上却变慢。
     这支持“某些目标表达改写能改变求解难度”，还不支持稳定的通用方法。

  3. 原设想不是完全被否定，但下一步应缩小研究问题：先自动识别监视器结构，
     再针对真正未闭合的内部关系，提供有来源对应的 RTL/状态更新片段。评价
     必须看是否闭合原目标、辅助关系证明难度和总成本，不能看 lemma 数量。
     如果内部关系仍保留整个CPU依赖锥，就需要研究可证明的模块边界合同；
     继续把完整匿名 BTOR 发给模型或只提高 token 上限，目前没有效果依据。
     这是后续待验证的方向，不是本轮已经实现的突破。
