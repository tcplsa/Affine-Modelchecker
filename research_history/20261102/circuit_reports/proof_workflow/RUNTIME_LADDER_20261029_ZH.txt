按耗时梯度选择 CV32E40X 任务
2026-10-29

先看结论

  900秒档已有一个实证成功：p18 原题普通 IC3 912.4 秒 SAFE；第一轮 LLM
  候选经“拆分 SMT + 剩余关系独立 IC3 + 组合”后，已证明同一原题 SAFE。
  此验收步骤已写成不含题目编号、节点编号的通用独立入口，自动重跑25.0秒。
  同一组候选整体交给普通 IC3 或 CIll，分别在300秒超时。
  25.0秒不包含候选发现；完整自动发现加验收的耗时收益还未端到端复测。
  p256 仍未被我们的方法解决。这是一个成功任务，不是普遍适用性的证据。

这轮要回答的问题

  之前直接挑战 1800 秒超时任务没有成功。这轮按用户建议，先选略低于
  1800 秒的任务，再试 900 秒附近的任务。目标是找到可重复的有效区间，
  不通过修改原性质、增加未经证明的假设或缩小硬件配置降低难度。

怎么选，避免事后挑成功例子

  从已有 1980 条历史记录里，固定 native_legacy4 配置，只选已经 SAFE
  或 UNSAFE 的 CV32E40X 样例。第一档 [1200,1800) 中取最接近 1800 的；
  第二档 [600,1200) 中取最接近 900 的。选择在新方法结果出现前冻结。

  主攻：p256，历史 SAFE 1600.384129 秒。
  下一档：p18，历史 SAFE 903.533242 秒。

  p256 的性质是调试触发器的 mcontrol6 hit 标志置位检查。
  p18 的性质是多操作指令异常后停止相关数据总线活动的检查。
  这里验证的是比赛模型中的该项性质，不是整个 CPU 的全部功能。

历史秒数为什么不能直接作为本轮对照

  历史记录来自 AIG、Native legacy BVE、四个随机种子并行副本；当时没有
  保留逐题日志和确切二进制哈希。本轮框架的输入是官方字级 BTOR。
  同名 AIG 和 BTOR 分别保存及计算哈希，没有宣称两种文件已经证明等价。

  本轮重新测普通 IC3：CIll 分支的同一 rIC3 二进制、一个核、16 GiB、
  seed=730001、总预算 1800 秒。原始初始化、转移、环境和 bad 均冻结。
  因而 1600 和 904 只是选题依据。最终以新基线确定当前配置下的难度，
  不能用历史四副本时间除以本轮单核时间宣称加速。

  所谓二分在这里是分档探测，不是有单调性保证的二分算法。两道性质即使
  属于同一个 CPU，难点也可能不同；求解器、格式和随机种子都会影响耗时。

本轮实验约束

  split 和 cill 各自至多两轮 DeepSeek，最多 131072 个推理及输出 token/轮，
  总预算 1800 秒/方法，后端单次 300 秒，SMT 单查询 30 秒。
  两种方法使用完整冻结 BTOR 上下文和相同预算。记录候选生成、失败尝试、
  查询生成与验收总耗时。两组提示及后端不同，不是单变量消融实验，也不是
  CIll 论文完整代理复现。本轮候选没有由主代理手工填写或改写。

  另外在 p256 原题上做 k=2、k=4 的直接归纳诊断：归纳步骤均 SAT。
  这是归纳方法暂时不充分，不是从复位可达的硬件反例。

如何判成败

  只有原始根目标闭合才计为成功。证明若干辅助关系不计作解决原题。
  性能收益统计所有 API 和证明成本；已有候选之后的验收时间另列。
  超时、归纳反例、候选被拒绝分别记录，不合并为电路 UNSAFE。
  若此档仍无新成功，保留负结果，先分析缺失关系，不自动无限追加调用。

已经取得的结果

  p18 的新普通 IC3 基线已 SAFE，912.409 秒，确实进入 900 秒档。
  纯 split + LLM 两轮仍 UNKNOWN，431.803 秒；p256 同组 UNKNOWN，378.385 秒。

  p18 第一轮 9 条候选中，有一条未通过单步归纳，其余义务及原目标的步骤
  已通过。这条关系为 H = (!node886574 || node1661)。node1661 的定义是
  {前一拍主时钟, 当前主时钟} == 2'b01，因此 H 的含义是：某个内部布尔
  条件为真时，当前必须是模型定义的主时钟上升沿。这一解释来自冻结 BTOR，
  不依赖给匿名节点猜测 RTL 名字。

  将 H 单独作为安全性质，保留完整原始 I/T/A，由同一 rIC3 独立证明。
  结果 SAFE，进程 23.449 秒，含框架开销 24.899 秒。该子证明没有假定原
  目标或其他候选成立。随后用 Z3 重放原检查中的覆盖、前提、初始化、可行性
  和其余步骤，并检查独立子目标确实等于 H；3.640 秒全部通过。

  因此现在有一份能够推出原始 p18 性质 SAFE 的组合证明：
    (1) H 已在原模型的所有可达状态成立；
    (2) 其他关系及原性质在初始状态成立；
    (3) 它们在 H 的帮助下经过一次原始转移仍成立。
  按归纳即可得到原性质在全部可达状态成立。没有把 H 当作未经证明的假设。

  这是第一次在本轮 900 秒档任务上完成原题组合证明，不是只证明辅助性质。
  首次由主代理调度后，已提取为 proof_workflow/residual_bridge.py：读取
  问题包和候选，重新生成拆分义务，自动选择唯一未闭合关系，独立 IC3 证明
  后组合。没有写入 p18 或其节点编号，整个固定候选过程实测25.009秒 SAFE。
  尚未将此策略接入 LLM 的逐轮循环或 C++ 入口；也没有因此证明整个 CPU、
  全部 SVA 或全部参数配置。

  不应拿 24.899 秒直接与 912.409 秒比较。两轮 LLM 已用的 431.803 秒、
  独立子证明和组合复核等所有阶段都必须报告。首次手工调度实验的相关阶段
  实耗之和约460秒；复用候选后的新自动验收是25.009秒，与两轮原探索阶段
  相加约456.8秒。这些均不包含主代理开发、分析、调度及等待其他组的间隔，
  不能写成实测自动流程墙钟；额外开发复测和对照均保留记录，未从账本删除。
  仅使用第一轮候选的理想流程更快属于事后估算，本报告不作为正式加速比。

  证据：p18-residual-helper/composition-obligation.json、p18-residual-plain/、
  p18-composition/result.json。保留 rIC3 证书；没有安装并运行 cerbtora，仍
  信任 rIC3 的 SAFE 结果、BTOR→SMT 翻译器及 SMT 求解器。

  额外对照已结束：第一轮全部候选和原目标一起交给普通 IC3，300.470秒
  TIMEOUT；交给 CIll，300.474秒 TIMEOUT。候选只作为待证明性质，不加
  环境假设，无新 API 调用。相同候选下，单独证明剩余关系确实提供了帮助。

  p256 新普通 IC3 基线在1800.379秒超时，因此历史1600秒没有在新配置复现。
  p256 的 split 两轮 UNKNOWN 378.385秒；CIll 两轮 UNKNOWN 1358.418秒。
  p18 的 CIll 两轮 UNKNOWN 1253.497秒。本轮两题、两方法共8次 API 调用，
  合计1,435,105 token（含输入、缓存及推理输出的服务端计数，不是费用）。
  新桥接入口在 p256 上返回 UNKNOWN，没有靠丢弃原目标制造成功。

新入口复现与边界

  在项目根目录执行（OUT 必须是新的目录；这里不会调用 API）：
    python3 -B proof_workflow/residual_bridge.py \
      verification/whole_core/runs/runtime-ladder-20261029/p18-package \
      --candidate verification/whole_core/runs/runtime-ladder-20261029/p18-paired/split/attempt-01/round-01/candidate.json \
      --out OUT --seconds 180 --cpu 28

  这是研究入口，当前只接纳第一条根义务已闭合且仅剩一个归纳义务的情况。
  多个残余、原根义务仍开着等情况如实返回 UNKNOWN，不修改原模型找捷径。
  两项测试通过：初始化/转移/环境篡改会被拒绝；原题为真但辅助关系会在
  第二步失败时，独立反例检查返回 CANDIDATE_REJECTED，不误报原题 UNSAFE。
  bridge-tests.log 保存测试结果，p18-auto-bridge/ 保存完整自动复测证据。

失败也揭示了什么

  p256 第二轮的 11 条候选，在上一轮记录的当前帧归纳反例上全部为真，
  没有排除那个反例。candidate-cti-audit.json 保存计算结果；缺失观测记
  null，不擅自补零。这是诊断，不替代证明验收。
  候选质量至少应分成“关系是否正确”和“是否能排除当前卡点”两项。
  p18 第一轮则有一条关系能排除反例，但需要可达性证明，单步归纳不够。
  这些结果支持试验混合证明后端，而不支持单纯无限增加 token。

下一步应验证的假设

  先把“候选只剩一个缺口时优先独立 IC3”接入逐轮流程，避免第二轮 LLM
  把有效但不满足单步归纳的关系删掉。再按相同规则选下一批未参与调试的
  任务，计入全部候选调用和失败尝试，从零复测。这一步完成前，最稳妥的
  结论是：900秒档已有一个原题成功实例，固定候选后的拆分与后端组合有效；
  尚没有证明该策略普遍有效，也没有得到自动端到端加速的稳定统计。
