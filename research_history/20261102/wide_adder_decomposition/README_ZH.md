# 64 位加法器拆分证明示例

这个示例只用于解释组合证明方法，不作为性能优势实验。

`formal_direct.v` 写出一个普通安全性质：上一拍输入有效时，本拍输出的 `{overflow,sum}` 必须等于完整 65 位加法；不成立即 `bad=1`。

拆分路线把 64 位加法分成四个 16 位合同：

```text
{c1,s0} = a0 + b0
{c2,s1} = a1 + b1 + c1
{c3,s2} = a2 + b2 + c2
{c4,s3} = a3 + b3 + c3
```

Yosys 分别检查四个局部 `local_bad` 永远为零；`WideAdderComposition.lean` 只使用四条局部合同，推出完整 64 位加法和最终溢出位正确。它展示的核心是：求解器处理固定宽度局部块，证明助手处理无歧义的组合逻辑。

运行：

```bash
./run.sh
```

纯组合加法通常不难，这个 64 位例子主要用于教学。研究实验应把同样方法用于真实 RTL 中带寄存器、使能、模式切换和延迟对齐的宽算术通路，再与同一性质的直接 PDR 比较。

本机实测均通过：整体三拍展开目标为 11179 个 SAT 变量、29782 个子句；四个局部合同合并检查为 2635 个变量、7063 个子句；Lean 组合定理通过。两组公式承担的工作不同，这些数字只说明拆分后局部查询更小，不作为求解器速度对照。
